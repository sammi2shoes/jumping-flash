# Single-motor bench recovery firmware

MotorRecovery targets the verified StickC Plus2 GPIO32TX/GPIO33RX MiniCAN wiring, RS05 CAN2.0 firmware0.5.0.14, motor1/host126,1Mbps. It requires the same ESP32+Bluepad32 Arduino core and M5Unified used for the successful controller diagnostic. Build environment motor-recovery. The spinner and second leg are not implemented.

RB/R1 is a held enable; left-stick X adjusts a position target at up to0.10rad/s within +/-5degrees of the measured position at each deliberate arm. Current1 A, watchdog20000 counts nominal1s, verified on configuration and again after enable. These are unloaded bench limits, not validated linkage limits and not a persistent calibrated leg coordinate frame. Do not attach/load the mechanism using these relative limits.

On boot and CAN return, STOP must be confirmed without fault flags; standard settings are written/read back; the position target is set to the current measured position while disabled. Automatic reports left by the observer test are switched off. The motor remains disabled until fresh Bluetooth input shows RB/R1 released with centered left stick for100ms, followed by a centered-stick RB/R1 press. Settings/target are prepared again before enabling, limits reapplied afterward and target aligned to measured position. Holding enable across reconnection never re-arms.

Bluetooth disconnect or >200ms stale controller data, release of RB/R1, Stick buttonA, serialx, a fault/warning, unexpected disabled feedback, or a failed read/target acknowledgement disarms and discards the old target. An explicit STOP is attempted, followed by1250ms without CAN control traffic so the tested motor watchdog can expire if the stop cannot reach the motor. Recovery first confirms STOP and settings; it does not clear faults, save parameters, calibrate, change IDs or enable automatically. TWAI bus-off recovery is handled while disarmed. Software has no queue of stale targets; single-shot transmissions are used. IMU attitude control, a weapon output, second-leg control, calibrated absolute leg limits and actual competition-rule verification are outside this sketch.

Simulated host checks exercise startup with no enable, motion bounds, CAN loss/quiet interval/reconnection at a changed physical position, held-enable gating, release/press re-arm, stale and disconnected Bluetooth, off-center enable rejection, button stop and rejected limits. ESP32+Bluepad32 compilation passed. No on-device run of this firmware is claimed. Bluetooth+motor behavior and timing remain hardware validation tasks; the previous watchdog bench tests do not establish this new controller's complete failsafe behavior or competition compliance.
